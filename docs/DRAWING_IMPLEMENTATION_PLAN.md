# 绘画规范与落笔依据：实施规划

适用版本：Line Atelier v4 · R3 底稿与平滑整合版。

本文跟踪实施状态。底稿与平滑已融合；正式规则统一维护于 [WORKFLOW_PRINCIPLES.md](WORKFLOW_PRINCIPLES.md)，已接入项目指令与网页状态接口。入口验证见 [DRAWING_PROTOCOL_VALIDATION.md](DRAWING_PROTOCOL_VALIDATION.md)。批次 basis 与独立会话记录已完成；[左眼试画](R3_LEFT_EYE_TRIAL.md) 的流程验证完成，依据运用与临摹一致性待补验。

## 1. 范围与现状

| 项目 | 当前事实 | 本规划要补齐什么 |
|---|---|---|
| 部位观察与定位 | `paint_inspect_context` 默认返回一张对照图、笔迹 ID、整图坐标；按需取完整几何或只取数据 | 沿用该原子工具，不另建观察向导 |
| 正式规范入口 | 项目 AGENTS 指向统一正文；网页状态接口默认返回同源全文及哈希；复制绘画要求共用正文 | 核对实际入口的加载记录；不能依赖用户点「复制」或只检查文件存在 |
| 落笔说明 | 单笔有 `intent`，批次可附 `basis`，修改和复核有 `note` | 已关联实际读取 ID、取坐标、落笔和结果图 |
| 操作记录 | 除页面活动、工程事件和复核外，独立会话日志保存实际调用与图片 | 已支持持久化和分页导出；文字活动日志本身仍不等于完整调用证据 |
| 自由度 | 模型决定采用哪些底稿、怎样画；上下文读取不改变工程 | 不增加「没读底稿就拒绝落笔」的拦截，不增加审核轮次 |

附件对比结论：用户上传的 HTML 是较早的完整返回版，仍含人工按钮、默认多张图片和每页 80 条记录；不含平滑工具。其 R3 笔迹和七个检查点与主版本一致。整合保留其底稿检索及多坐标能力，采用用户随后确认的模型优先接口：默认一张图、每页 24 条、可分页、详情按需；保留当前平滑能力。

## 2. 第一项：统一正文与绘画入口

### 2.1 单一规范正文

直接完善既有 `docs/WORKFLOW_PRINCIPLES.md`，在核心原则、两轮审核和九项质量标准中持续加入开始任务、每个部位的执行循环、坐标使用与记录边界。不另建第二份正式规范。

`scripts/sync-drawing-protocol.mjs` 从该正文生成网页文档和带 SHA-256 的模块；网页状态结果与复制绘画要求使用同一模块。开发启动、测试和构建时同步，`npm run check:protocol` 可只读检查是否过期。哈希对应按 LF 归一化的 UTF-8 正文，用于识别版本，不代表模型已经理解或执行。

### 2.2 加载位置

| 执行环境 | 已接入位置 | 必须验证的实际行为 |
|---|---|---|
| 在项目工作区执行的 Codex | 仓库根 `AGENTS.md` 要求实际绘画前读取统一正文；当前外层迁移目录另有指引指向真实仓库 | 新绘画任务加载适用的项目指令，并实际读取正文；代码维护不触发作画 |
| 从对话打开工作台作画 | `paint_get_state` / `window.paint.state()` 默认返回 `drawingProtocol` 的来源、哈希和全文 | 工具结果中的正文实际进入模型上下文；仅检查页面资源存在不足以证明加载 |
| 网页接口说明与复制绘画要求 | 链接或嵌入同源正文，已有参数指南保留 | 网页、单文件构建和仓库正文一致 |

网页调用者无需读取本地文件或安装专用 skill：从已有状态工具取得全文即可。该工具说明明确它是作画起点；同一版本已经读过时可用 `includeProtocol:false` 只返回版本信息。默认每次返回正文，不用页面级“已读”标记，以免新模型接手同一页面时漏读。入口仍不强制拦截提交，不能保证所有调用者都会遵循。

### 2.3 不增加的工序

不要求每笔重新取整图、不增加思考表单、不要求先选候选方案、不给每笔加一次强制审核。小组大小由语义决定，例如上睑及相关睫毛是一组；不要一次提交大量互不相关部位来绕开反馈。局部与整体回看沿用原流程；1F 仍是两轮。

## 3. 第二项：每组一条依据，关联实际操作

### 3.1 最小接口改动（已支持）

在现有 `paint_submit` / `paint_revise` 批次上增加可选的 `basis`，而不是新建「填写依据」工具：

```json
{
  "basis": {
    "guideIds": ["已有底稿笔迹ID"],
    "note": "本组画左眼上睑；沿用内眼角，外眼角上提。"
  },
  "commands": ["此处代表原有笔迹对象，实际调用需使用合法对象"]
}
```

以上展示批次结构；commands 中的占位文字须换成合法笔迹对象才能执行。几何、图层、笔压等原有字段保持原用法。`basis` 不包含长篇推理；一组记录一句，不复制到每根笔迹。

程序自动分配组 ID 和调用 ID，记录调用前后 revision、生成或修改的笔迹 ID、成功或失败。非清稿阶段省略依据时记录为未提供；进入 clean 后，`basis.guideIds` 必须覆盖每个实际修改目标，并引用同部位保留底稿，否则程序拒绝修改。

### 3.2 证据保存在会话调用层

上下文读取继续不改作品、图层、时间轴、撤销栈或复核。调用证据记录在独立会话日志，不塞进绘画的撤销历史。统一覆盖 WebMCP 与受支持的页面 API 调用入口，避免通过其中一路操作时漏记。

| 事件 | 自动保留的最小字段 | 能证明与不能证明的内容 |
|---|---|---|
| 读取上下文／坐标 | 调用 ID、工具名、query/objectId/region、revision、实际返回的笔迹和锚点 ID、分页情况、参考访问状态 | 证明返回过这些依据；不能证明模型已正确理解 |
| 获取观察图 | 图像标识、范围、缩放／翻转变换、revision、播放位置、关联调用 ID | 证明当时生成了哪一张图；须与对话中的实际图像呈现结合，不能只存 Base64 文本就称看过 |
| 提交／修订笔画 | 组 ID、basis、结果笔迹 ID、前后 revision、实际接受参数、成功或失败 | 可核对用了哪些坐标及如何修改；不自动判断这些坐标在美术上是否合理 |
| 画后获取图 | 图像引用、范围、revision、播放位置、关联笔画组 | 可检查结果图是否包含该组执行后的结果，而非旧图或未完成回放 |

图片本体按需保存为证据附件，主日志只存引用与摘要；哈希用于校验对应关系，不能替代图像本体或模型实际看到图像的记录。由现有工程导出入口附带导出会话证据，或通过按需读取工具分页获取，不增加每组必须调用的记录工具。

如果一张复看图覆盖连续两组，可关联两组；多个部位共用整体底稿也可引用同一条依据。相关几何发生变化时，旧证据仍保留但须标出其 revision，不能冒充当前观察。

### 3.3 可核对性与边界

核对时关注「读了什么 → 改了什么 → 看到了什么结果」，不展示或要求模型的完整内部思考。短说明、复核的 evidence 文本字段、页面打印了工具名，都不能独立证明执行链完整。

不实现自动“遵循度评分”或先检查再允许落笔。遇到缺失步骤，仅在按需回看日志时标为未记录；据此改善指令。任何不拦截方案都不能百分之百保证模型遵循。

## 4. 实施顺序与小部位验证

| 顺序 | 工作 | 完成条件 |
|---|---|---|
| 0（本轮） | 合并附件能力、保留单图默认与平滑、澄清源点与渲染轨迹 | 同一工作台具备两项能力；原 R3 工程与检查点不丢失 |
| 1（已完成入口验证） | 既有规范单一正文与实际入口加载 | 仓库根和当前外层目录的新任务均实际读取正文，网页及单文件 WebMCP 返回同源全文；详见 DRAWING_PROTOCOL_VALIDATION.md，不代表真实绘画验收 |
| 2（已完成） | 批次 basis 与独立会话日志 | 可选依据、实际 ID／几何／revision 和原图引用自动记录；支持两种接口，读操作不改变作品 |
| 3（待补验） | 在 R3 副本的左眼做一组真实试画 | 读图、取坐标、落笔与复看已执行；还需验证底稿如何支持修改，以及修改是否更接近参考 |
| 4（未开始） | 推广到整幅绘画 | 第 3 项补验后再推进；保持小组循环和简短依据 |

左眼验证必须检查：

1. 模型先取得左眼参考、当前画布、隐藏眼部占位／透视线及实际坐标。上下文歧义或分页截断时有明确处理。
2. 提交前依据里出现工具真实返回的底稿 ID；至少能核对一处沿用坐标或显式偏移，不能仅凭一句“参考了底稿”。
3. 只提交一小组左眼笔迹，落笔结果返回实际笔迹 ID；若动画未完，先 finish 再看结果。
4. 实际呈现并观察执行后的图，revision 和范围对应；据此继续或修线。工具返回图片字符串本身不等于模型已经视觉观察。
5. 故意没有底稿或底稿明显偏位的情形中，模型说明、补稿或改稿，仍可自由落笔；不触发新硬门槛。

第 3 项已保存 22 次调用、7 张原图和独立工程，证明流程已执行。下一步选取与参考存在明确偏差的局部，说明底稿依据，修改后同尺度对比，核对偏差是否缩小。规范已据此精简修订，实际效果仍待补验。
