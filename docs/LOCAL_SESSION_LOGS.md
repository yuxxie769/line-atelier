# 自动本地会话日志

在仓库内运行 `npm run dev`，通过 `http://127.0.0.1:5173/` 使用工作台。每个会话自动写到 `logs/sessions/<sessionId>.json`，独立于工程文件。保存原有 `createSessionEvidence` 完整快照，包括调用参数、结果、修改数据、图片索引及 PNG data URL；不压缩、分页或删图片，也不改变原有计数语义。

返回实际图片的调用会额外记录 `imageRead`，其中包含图片读取完成时间、数量和图片 ID／参考卡图片文件。下一次模型工具调用开始时，读图事件写入 `nextAction`，下一次调用同时写入 `sinceImageRead`；两处都保存 `delayMs`，表示从图片返回完成到下一步开始的毫秒间隔。尚无下一步时不生成该间隔；它记录工具调用时序，不证明模型已经理解图片。

浏览器 IndexedDB 仍是原有会话存储。启动时自动补写该工作台数据库中保存的会话；后续调用更新本地快照。服务器先写临时文件再替换正式文件，较旧快照不能覆盖更多事件的文件。写入失败保留待写队列，每 15 秒重试；刷新后从 IndexedDB 再补写。页面顶部与 `paint_get_state.localEvidence` 区分本地写入成功／待写入，原有 `callEvidence.persistence` 仍只表示原来的会话存储状态。

本地接口只接受回环连接及同源 JSON POST，目标固定在日志目录，不接受任意路径。日志目录已加入 Git 忽略规则。单次完整快照上限 512 MiB，超限会明确待写入而非静默截断。大日志每次完整重写会增加磁盘和内存开销。

自动写文件需要运行本地服务；发布的静态页面或直接打开单文件 HTML 没有该服务时显示待写入，保留原有 IndexedDB 与手动导出能力。它不自动记录 Codex 对话、任意浏览器截图或未经过现有会话记录器的操作，也不能证明模型实际看懂了图片。这里的“全量”是原有会话日志的全量保存。

问题状态另存在工程 `partIssues`；审核引用 `observationIds`。这些功能的新增调用仍由原有会话记录器照常记入日志。观察凭据由当前运行实例生成，恢复或重新载入后需要重新取图核验，旧工程的通过文字不会自动恢复为有效通行证。
