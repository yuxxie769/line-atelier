# 袖肘工程实测

使用保留的白发坐姿人物工程，在独立副本中替换 `ink-raised-sleeve`。复用上一轮已观察的袖肘源规划，检验它接入当前网页处理代码后的行为，不把相同规划重复执行称为新的造型方案。

`run.mjs` 直接提取并执行当前 `app/app.js` 的普通线检查与复合返修展开函数，再通过真实 PaintEngine 替换、渲染与导出。它没有运行浏览器 WebMCP 会话、参考章节读取门或图像检查授权循环，因此只证明这一段接口处理及渲染，不是完整网页端到端验收。

初测发现：清稿阶段的普通复杂长线若自行标注 subphase 为 rough，会逃过复杂度检测。已修复为按页面当前阶段检查；保留该回归用例。

复测 8 项通过：未分类拒绝、复杂线声明简单仍拒绝、错标 rough 仍拒绝、真实简单扫线接受、手写 compoundId 拒绝、实际四笔超额拒绝、三笔替换成功且其他笔迹不变、完整方法正文随状态返回。

实际查看 `results/comparison.png`：接头连续，放大下没有明显断缝或黑结；袖肘下半段比原先匀圆弧略带折向，局部粗细有变化。正常局部尺度改善较小，尚不足以让整段布料变得明显像人手绘；源规划、内部褶皱与体积关系仍决定主要观感。

原工程未覆盖。候选工程为 `results/candidate.line.json`；完整输入、展开结果及测试记录分别为 input.json、expanded.json、report.json。
