# v1 定型后的三个新位置

用户要求先固定上一轮三号方案，再选三个位置试画。本轮使用已保存的 `scripts/drawing/compound-v1.mjs`；方法维护于 `docs/drawing-methods/COMPOUND_V1.md`，核心规范中添加入口，并由规范同步脚本生成网页文档副本。

## 执行范围

承接 `../20260909-local-turn-trial/results-scheme3/candidate.line.json`，保留上轮膝部结果。依次完成脸颊到下巴、抬臂袖肘、鞋头，每组生成三笔，逐组实际查看参考／底稿／旧清稿和画后对照，再汇总整图。

本次是同一条离线试画工作流，不是在网页提交正式清稿批次。没有创建网页观察凭据或正式通过记录，也没有覆盖原稿。方案已定型为脚本级 v1，尚未新增正式网页绘画工具。

## 底稿承接及观察

- 脸颊下巴：旧细化文件中的 `face-jaw`（rough 层）提供颊部走势和下巴 `(334,248)`。本次保留现清稿两端与下巴位置，重写两侧局部走势并减轻线重；接点连续，没有明显黑结。结果以保留形体、调整线条轻重为主，不声称脸型已经完全贴近参考。
- 抬臂袖肘：`raised-sleeve` 提供袖侧、肘下及袖底的位置依据。当前清稿比底稿更匀圆，本次通过独立曲段恢复更明确的肘部方向变化；袖底 `(278,413)` 及两端保持。局部比原长圆弧更有转向，但内部衣褶和整袖体积简化没有解决。
- 鞋头：`shoe-vamp`、`shoe-mass`、`shoe-sole` 提供鞋面与鞋底关系。本次只动鞋面前缘 `ink-shoe-vamp`，保留两端、搭扣与鞋底。前端略平、收笔更细；小转折没有形成凹坑或双边。不能据此认为材质已经画出来。

先后实际查看每处 `*-before-context.png`、`*-comparison.png`，最终查看 `overview.png` 和 `full.png`。三个部位变化均克制，袖肘的形状变化相对更可见。参考 600 × 849，微小折向属于用户要求的风格化解释，不是逐像素得到的事实。

本轮几何和压力同时改变，没有对照隔离各因素的美术贡献；自动搭接是否保留源轨迹由数值测试独立验证。不能把全部差异归因于自动分笔，也不以三笔数量作为质量指标。

## 保存与验证

- `inputs.mjs`：三个局部的模型输入，无手写搭接尾端。
- `results/*-input.json` 和 `*-compiled.json`：实际源输入及程序生成的三笔。
- `results/candidate.line.json`：三处合并的可编辑候选，替换三条旧命令为九条，其他 198 条命令（含上轮膝部）一致。
- `results/overview.png`：三个位置同尺度前后对照；每处 `*-comparison.png` 有接头放大和彩色笔组说明。
- `results/checks.json` 与各局部 checks：源文件不变、端点保持、源采样点保留、搭接压力保持、候选导出重载一致。

定型 v1 与已认可膝部原型输出完全一致（显式参数相同）；新增保护会拒绝额外平滑和不支持的输入。相关回归测试 14/14 通过，包含 v1、旧接笔原型、小转折及规范同步。`npm run build` 与 `npm run check:protocol` 通过。构建重新生成既有发布产物，不表示已线上发布。

复现：设置 `CODEX_PRIMARY_RUNTIME_NODE_MODULES` 指向包含 `@napi-rs/canvas` 的依赖目录，运行 `inspect-render.mjs --inspect`，再分别 `run.mjs jaw`、`run.mjs sleeve`、`run.mjs shoe`；逐组查看后用 `run.mjs --assemble` 合并。脚本只重写本目录 results 中的生成产物。
